# Lighthouse of Article MVP 実装開始計画

> **For Hermes:** Use this plan task-by-task, verifying each step before moving forward.

**Goal:** SupabaseとNext.jsの開発基盤を整え、arXiv検索機能を実装できる状態にする。

**Architecture:** Next.jsの画面とRoute Handlersを1つのアプリケーションで管理する。サーバー側APIからarXivとSupabaseへ接続し、将来の要約AI APIも同じ境界に置く。MVPでは認証を実装せず、個人利用として開始する。

**Tech Stack:** Next.js, React, TypeScript, Tailwind CSS, Supabase PostgreSQL, `@supabase/supabase-js`

## 実装前提

- Supabase無料プランを利用する
- PDFは保存しない
- 検索結果・保存論文一覧は1ページ20件
- 論文の重複判定は`arxiv_id`で行う
- 要約は保存済み論文のabstractのみを対象にする
- APIキーをクライアントへ渡さない

## M2-1: Supabaseプロジェクトを作成する

**目的:** 接続先となる開発用Supabaseプロジェクトを用意する。

**作業:**

1. Supabaseにログインする
2. 新しい開発用プロジェクトを作成する
3. データベースリージョンを日本からのアクセスに適したリージョンから選択する
4. Project URLと匿名キーを控える
5. Service Role KeyはブラウザやGitへ公開しない

**検証:**

- Supabase Dashboardを開ける
- SQL Editorを利用できる
- Project URLと匿名キーが取得できる

**注意:**

Supabaseの認証情報が必要な外部操作のため、CLIから自動作成せず、ユーザーのアカウント環境で作成する。

## M2-3: Supabase接続設定を追加する

**作成:**

- `.env.example`
- `.env.local`（Git管理外）
- `src/lib/supabase/server.ts`
- `src/lib/supabase/types.ts`

**環境変数:**

```text
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
OPENAI_API_KEY=
```

**方針:**

- サーバー用Supabaseクライアントを共通化する
- `.env.local`を`.gitignore`へ追加する
- `.env.example`には値を入れない
- Service Role Keyは使用しない

**検証:**

- アプリ起動時に環境変数不足を検知できる
- サーバー側からSupabaseへ接続できる
- `.env.local`がGitの追跡対象外である

## リスクと保留事項

- Supabase無料プロジェクトは長期間非アクティブだと一時停止される可能性がある
- arXiv APIのレート制限に配慮する
- 要約AI APIの料金と入力文字数はM6で制御する
- 認証なしで公開デプロイしない
- Next.jsのバージョンやTailwindの初期設定は、実装開始時点の公式推奨構成に合わせる
